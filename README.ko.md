# Super Figma Pipeline

[English](README.md) | [한국어](README.ko.md)

Figma Dev Mode나 공식 Figma MCP 없이 디자인을 읽고, 서비스 코드를 분석해 코딩 에이전트가 대상 애플리케이션에 디자인을 구현하도록 돕는 로컬 파이프라인입니다.

**현재 개발 중입니다. 문서 기준일: 2026년 9월 21일.** 디자인 수집, 소스 분석, 포탈 작업 관리, 네이티브 검증 코드와 개별 테스트가 구현되어 있습니다. 4개 케이스 전체의 최종 통합 검증과 릴리스 검증은 아직 완료되지 않았습니다.

## 동작 방식

1. 외부 Playwright/Scripter로 Chrome의 Figma 파일을 읽거나, 페어링된 Figma 데스크톱 개발 플러그인으로 접근합니다.
2. 디자인 구조, 컴포넌트 속성, 변수, 스타일, 상호작용과 사용 가능한 에셋을 수집합니다. 누락되거나 일부만 수집된 항목은 그대로 표시합니다.
3. 지정한 레거시·레퍼런스 코드에서 컴포넌트, 구현 규칙, 의존성, 관련 API·데이터·인증·설정 패턴을 분석합니다.
4. 포탈 도구를 통해 코딩 에이전트에 디자인과 코드 근거를 전달합니다. 에이전트가 실제 구현 파일을 제출하며, 계획을 시작하는 것만으로 애플리케이션이 완성되지는 않습니다.
5. 별도 작업 복사본에서 네이티브 검증을 실행하고, 구현 화면을 Figma 내보내기 이미지와 비교한 뒤 검증된 변경을 지정한 대상에 적용합니다.

코드 패턴을 학습한다는 것은 선택한 저장소의 코드를 분석하고 근거에 따라 재사용한다는 의미입니다. 별도의 모델을 훈련하는 기능은 아닙니다.

## 구현 대상 4가지

| 케이스                        | 입력                                      | 구현 범위                                                                                                               |
| ----------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| C1: 신규 서비스               | Figma와 선택적인 서비스 레퍼런스          | 레퍼런스가 있으면 C3, 없으면 C4로 진행합니다.                                                                           |
| C2: 레거시 서비스             | Figma와 기존 대상 서비스                  | 관련 구현 패턴을 유지하면서 UI와 필요한 API·백엔드·데이터·인증·연동을 구현합니다.                                       |
| C3: 레퍼런스 기반 신규 서비스 | Figma와 명시적으로 선택한 레퍼런스 서비스 | 참고할 구조와 라이브러리를 활용해 독립적으로 동작하는 포탈을 만듭니다. 필요한 계층이 레퍼런스에 없으면 추가 구현합니다. |
| C4: 레퍼런스 없는 신규 서비스 | Figma, 서비스 레퍼런스 없음               | 프론트엔드만 구현합니다. 라우팅, 반응형 컴포넌트, 로컬 상태, 데모임을 명시한 어댑터를 포함합니다.                       |

**프론트엔드만 구현하는 경우는 C4뿐입니다.** C3의 레퍼런스가 프론트엔드뿐이어도 필요한 서비스 범위가 자동으로 줄어들지는 않습니다. 기반으로 참고한 오픈소스 3개를 서비스 레퍼런스로 자동 취급하지 않습니다.

## 개발 환경 준비

Windows, Node.js 24, 저장소에 고정된 `pnpm@11.24.0`을 사용합니다. 개발 검증은 별도 작업 복사본에서 실행합니다. Docker는 사용하지 않습니다.

저장소 루트에서 실행합니다.

```powershell
cd service
corepack pnpm install --frozen-lockfile --ignore-scripts
corepack pnpm build
node packages/cli/dist/index.mjs help
```

관리·포탈 명령을 사용하려면 전용 터미널에서 로컬 데몬을 시작합니다.

```powershell
node packages/mcp/dist/daemon-entry.mjs
```

해당 터미널에서 `Ctrl+C`를 누르면 종료됩니다. 다른 터미널의 `service/` 경로에서 상태와 도구를 확인합니다.

```powershell
node packages/cli/dist/index.mjs status
node packages/cli/dist/index.mjs tools list
```

MCP 클라이언트에는 `node`와 `service/packages/mcp/dist/index.mjs`의 절대 경로를 등록합니다. 포탈 계획, 데스크톱 연결, 검증 명령은 [서비스 README](service/README.md)를 참고하세요.

## 제공된 Figma 디자인 읽기

Chrome에서 [테스트용 eCommerce 디자인](https://www.figma.com/design/4IBhv1d8hEclifZQrOYxHS?node-id=0-1)을 열고 파일 접근 권한이 있는 계정으로 로그인합니다. `chrome://inspect/#remote-debugging`에서 원격 디버깅을 활성화하고, Chrome이 연결 허용 창을 표시하면 직접 승인합니다.

Chrome 경로는 GPT 내장 브라우저 대신 외부 Playwright와 Scripter 플러그인을 사용합니다. 현재 CLI는 열려 있는 탭에 연결하며, 해당 계정·파일에서 Scripter를 사용할 수 있어야 합니다. Chrome 자체의 디버깅 권한 창은 아직 허가받지 못한 Playwright 연결로 대신 누를 수 없습니다.

빌드 후 `service/`에서 실행합니다.

```powershell
node packages/cli/dist/index.mjs chrome-inspect --url "https://www.figma.com/design/4IBhv1d8hEclifZQrOYxHS?node-id=0-1" --out "C:\figma-inspections\ecommerce"
```

Chrome 경로에는 Figma 데스크톱 앱이 필요하지 않습니다. 데스크톱 경로를 사용하려면 생성된 개발 플러그인을 처음 한 번 등록·실행하고 페어링해야 합니다. 앱 설치나 실행만으로 연결되지는 않습니다. 두 경로 모두 Dev Mode나 공식 Figma MCP를 요구하지 않습니다.

## 현재 진행 상태와 남은 작업

최근에는 비동기 사전 검사 중 취소된 요청이 Figma 변수를 생성하던 문제와, 브라우저 속성 검사 후 페이지·내부 스크롤 위치가 바뀌던 문제를 수정했습니다. 관련 **테스트 37개**, MCP·플러그인 타입 검사, 린트를 통과했습니다. 이는 해당 수정의 검증 결과이며 전체 릴리스 검증은 아닙니다. [수정 보고서](docs/reviews/2026-09-21-cancellation-and-scroll-fixes.md)에 근거를 기록했습니다.

남은 작업은 다음과 같습니다.

- 생성한 코드와 실제 적용한 코드가 수집된 디자인 값·컴포넌트·에셋을 사용하는지 확인하는 검증 완성
- 실행 기록을 유지하는 스타일·텍스트·오버라이드·변형·모션·내보내기 작업 완성: 일부는 아직 모델이나 제안 단계
- 인터페이스 호환 조건, 기능 지원 정보, 생성 산출물, 목록에 등록된 오픈소스 기능 69개의 활용 상태 갱신
- 디자인 구조와 에셋을 함께 담는 이동 가능한 오프라인 수집 패키지 구현
- 현재 서비스로 실제 Figma 연결 및 대표 C2·C3·C4 통합 테스트 완료: C4의 React/Vite·Vue/Vite와 C1의 분기 포함
- 최종 전체 코드 리뷰 2회, 타당한 지적 수정, 깨끗한 소스 기준 검사와 Windows 패키지·릴리스 검증

세부 내용은 [현재 구현 범위](docs/plans/2026-09-07-portal-four-cases-plan.md), [남은 작업 계획](docs/plans/2026-09-14-remaining-work-plan.md), [개발 체크포인트](docs/reviews/2026-09-15-development-checkpoint.md)에 있습니다. 과거 보고서는 작성 당시의 기록이며, 체크포인트에 적힌 버그 2건은 9월 21일 수정 보고서에서 해결을 확인했습니다.

## 검증 범위와 한계

네이티브 검증은 별도 작업 디렉터리에서 현재 사용자의 권한으로 실행합니다. 파일 해시, 검토된 실행 프로필, 시간 제한, 소유한 프로세스 정리 기능은 **운영체제 수준의 파일시스템·네트워크 샌드박스를 제공하지 않습니다.**

애플리케이션 미리보기 검증에는 헤드리스 Firefox를 사용하고, Chrome은 Figma 원본 접근에 사용합니다. 소스 검사, 실제 디자인 수집, 화면 비교, 실제 API·데이터·인증 동작은 각각 별도로 검증합니다. 빌드 성공이나 모의 API 테스트만으로 C2·C3가 완성됐다고 판단하지 않습니다. 다른 호스트 운영체제의 최종 네이티브 검증은 완료되지 않았습니다.
