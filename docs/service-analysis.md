## Purpose and Scope

The service connects Figma design evidence, explicitly selected application repositories and a coding agent. It collects design structure and assets, analyzes relevant source code, coordinates coding leases and submissions, and requires candidate validation, guarded application and applied-target validation. Starting a plan does not itself produce a finished application. Code-pattern learning means source analysis and reuse, not model training.

The [active four-case plan](plans/2026-09-07-portal-four-cases-plan.md) remains authoritative. C1 routes to C3 when explicit references exist and C4 otherwise. C2 extends a legacy portal while preserving relevant service behavior. C3 creates an independent portal from read-only references and requires every relevant service layer. Only C4 is frontend-only; its frontend routes, responsive components, local state and demo adapters must be explicit.

The browser policy is Chrome-only. Capture, browser tests and owned headless previews select installed Google Chrome through Playwright's Chrome channel. The retained paired Figma Desktop plugin is a local design workflow, not an alternative browser engine. Figma MCP integration accepts only Figma's official remote and local servers. Primary live testing uses Chrome, Playwright and authorized remote control of Figma Web; official reads supplement comparison when available.

The owner's October 2 correction requires every service test step to use service-owned tools. Codex browser control, CUA and external Codex connectors are prohibited substitutes. Official MCP acceptance must use the service's own integration. Historical connector observations are supplemental only. See the [service-owned restart](testing/2026-10-02-service-owned-resume/README.md) for the implemented repairs, native environment and actual current limits.

Firefox was present in the baseline's split-browser architecture: the baseline MCP README assigns the existing Chrome session to Figma and headless Firefox to application previews. Production preview launch, native runtime environment, browser-evidence schema, required tests and CI installation all implemented that choice. These active paths now use installed Google Chrome in separately owned sessions. A current scan of service packages/scripts, package configuration, CI and project instructions found no Firefox, WebKit or Gecko runtime references. Dated historical reports and preserved upstream lineage remain historical evidence.
