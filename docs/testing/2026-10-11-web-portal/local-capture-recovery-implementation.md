## Implemented behavior

### Explicit disposition separate from original outcome

The closed recovery allowlist is `chrome.inspect.ui`, `chrome.inspect.runtime`, `chrome.inspect.page-api`, `chrome.inspect.scripter`, `chrome.export`, `chrome.copy.svg` and `chrome.copy.png`. Eligibility requires a feature job that is unknown, non-read-only, composite, has zero daemon operations and a non-null workspace. Journal-backed, tool, null-scope and other composite uncertainty remain unsupported. No-op Inspect is no longer advertised for an unsupported local composite.

`prepare-recovery` obtains a one-use sixty-second challenge bound to the exact original row fingerprint and canonical workspace identity. The binding uses authenticated registry availability, canonical path and local directory identity. `abandon-local` checks that challenge, exact confirmation, supplied reason/evidence hashes, current producer/quiescence, and final workspace binding and expiry inside the serialized commit. A consumed or uncertain request requires readback; it is not automatically repeated.

The mutation writes only a separate `fenceDisposition` containing `owner-abandoned`, actor, timestamp, row/workspace hashes, reason/evidence references, quiescence category and durable activity ID. It does **not** change the original unknown status, original `updatedAt`, creation/deadline, arguments hash, target, error, output or evidence. Only this exact acknowledged row stops contributing to the existing central mutation-fence predicate. Other unknowns still block overlapping workflows and null-scope administration. The action dispatches no original command, resolves no daemon operation and changes no permission.

A real runtime producer promise is tracked independently of the caller-facing cancellation race. Current source initialization, deferred open/select intent, pending helper RPCs, failed cleanup and retired-generation work prevent recovery. Legacy rows additionally require the explicit owner assertion `priorProducerRetired:true`. The recorded category is `operator-asserted-prior-runtime`, not machine proof that historical effects did not occur. Reason/evidence hashes are owner-supplied review references; the service does not validate private evidence contents or the truth of that historical assertion.

Audit preparation must persist before disposition publication. The disposition itself contains a persistent decision receipt. Final activity-settlement failure does not redispatch or erase an already committed disposition; activity health exposes the warning and readback remains necessary. This reuses the existing serialized atomic JSON publication convention. Normal restart persistence and real publication failure were tested; power-loss/fsync durability and adversarial same-user path replacement were not established.

### Prospective failure proof and physical quiescence

Only the internal CLI factory can create a pre-effect failure receipt. A private WeakSet and WeakMap bind its exact error identity, invocation ID and mutable effect state. The public library exports only the read-only checker `isLocalCapturePreEffectFailure`; the factory is absent from the shipped library namespace. The portal calls the checker supplied by the actual imported CLI library, preserving identity across separately bundled package boundaries. Matching messages, codes, prototypes and foreign invocation IDs are not proof. A later effect invalidates an earlier genuine brand.

Before dispatch, the command marks opening/selection intents, focus initialization and every relevant capture/failure-folder creation. After that boundary, uncertainty remains unknown. A genuine newly executed pre-effect failure can become failed/cancelled without creating an unknown fence. No old row is reclassified. The wrapper preserves safe typed cause codes through the existing closed diagnostics projection, independently of proof authority.

The Chrome owner observes actual selected-session initialization, late cleanup and retiring generations. Copy bounded RPCs, export raced observations/trials and physical restoration promises remain tracked after logical cancellation. Failed cleanup persists across endpoint replacement and blocks new source commands. Helper work is invocation-bound, preventing a different pending invocation from falsely changing a known completed capture's status. A fulfilled capture with unconfirmed own cleanup is reported as unknown rather than successful.

Scripter snapshot and asset evaluation/cancellation RPCs are tracked. **Interrupted or failed Scripter work quarantines the current owner even after browser evaluation/cancel promises settle.** Posting cancellation does not acknowledge retirement of an already-issued Plugin API export. Per-asset error swallowing cannot erase this uncertainty. The owner is not automatically cleared by time, a message or a new connection. Historical continuation still requires reviewed producer retirement and the explicitly labeled legacy assertion.

This is observation of service-owned promises/intents and cleanup, not proof of the original Figma/capture outcome. Playwright cannot atomically cancel an already-issued click without closing the borrowed page. The existing exact Design Mode dialog guard, ordinary non-forced click, blob capture/byte limits and source-session ownership remain unchanged.

Selection/action/disposal aborts or invalidates stale polling responses. Terminal unknown recovery drafts are not polled. The feature input form and unsent preview remain intact.
