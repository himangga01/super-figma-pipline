## Implemented scope and architecture

The login-free same-origin portal now presents both the daemon's own OAuth mode and legitimate externally provisioned own-service token-reference mode. It receives only environment variable names and installed secret-free client-contract references/digests. Client-ID/secret values, tokens, PKCE verifier, OAuth state/code and actual authorization URLs have no UI/configuration/feature-result fields. Desktop stays separate and clears remote references from its submitted configuration.

Settings expose explicit status, start, cancel, local logout and refresh. Saving a name does not set the daemon environment or prove Figma client eligibility. Missing approved contract/environment prerequisites remain useful blocked states with no automatic login, metadata discovery, refresh, probe or consent handoff. The panel labels an operator-installed contract as a declaration, separates observed server authorization, and never claims full capture or an eight-hour data grant from login. Probe readiness matches the separate `lastProbe.authBinding` tuple and prior local revision/provider checks.

Active status polling is read-only, single-flight and bounded. It keeps unsaved references, workflow drafts, focus and caret. An action retires the previous poll epoch, preventing a late old status from overwriting cancellation. Unchanged auth content does not replace controls. Errors display only closed codes/messages, including the existing unknown-mutation fence, and never echo an arbitrary transport message.

A dedicated `/figma-auth-consent` document opens through a manual link in a separate tab. It performs only local read-only bootstrap/status requests on load. Manual Continue rechecks the exact current provider/configuration/auth generation and flow, then submits a native POST with exactly `csrf`, `providerInstanceId`, `configurationGeneration`, `authGeneration`, and `flowId`. It never obtains an authorization URL through JSON, begins login on GET, approves Figma/native consent or writes browser storage. Query/hash input prevents enabling the form. Disposal clears hidden fields. The prior portal and source Chrome remain separate.

The dedicated document uses **same-origin referrer policy**, while the normal portal, private handoff 303 and callback retain no-referrer. Actual Google Chrome sends `Origin: null` for this native POST under no-referrer; the initial stricter-privacy document therefore failed the required exact Origin guard. Changing only the canonical query-free document header/meta preserves exact native Origin and suppresses cross-origin Referer. Strict Origin/Host/fetch-site/form bounds remain intact. The portal/control relay owner independently implements that route/CSP/303 contract; this UI does not weaken global guards.

Public CLI now exposes `figma-mcp auth status|configure|start|cancel|logout|refresh`. Mutations use explicit provider/configuration/auth generations; start/refresh use the original absolute deadline. Configuration accepts only reference names. Safe status is parsed through the shared closed runtime contract. Start prints a fixed relative portal-view path and manual instructions, never an authorization URL, and never opens a browser. All six commands appear in the public feature catalog, taking the prior 58 unique CLI entries to 64. No general MCP self-approval or handoff-URL feature was added.

Terminal `figma-mcp probe/read` now use the existing ControlClient and the same daemon provider as portal probes and generation. `--oauth-token-env` is a name compatibility check against the daemon's external-token configuration, not a lookup/copy of the CLI process value. Endpoint/node/tool validation still occurs before requests; Desktop never receives a remote reference. Original SDK-direct CLI fixtures are preserved, while command tests now verify the daemon boundary. SDK/provider acceptance remains the separate daemon/engine owners' responsibility.

The separate [approval repair](portal-approval-pointer-repair.md) fixes unchanged-job pointer target replacement and visibly enabled controls during an ignored busy request. Its production source and retained UI regression remain unchanged in revision 2; only its owned proxy test lifecycle changed after review. It does not replay the expired/cancelled actual grant request or alter any policy, fence, deadline or unknown outcome.
