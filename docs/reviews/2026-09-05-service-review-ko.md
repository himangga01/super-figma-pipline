# 서비스 컨셉, 코드 리뷰 및 후속 작업 — 2026-09-05

## 판단 기준

제품의 주목적은 **Dev Mode와 Figma 내장 MCP를 사용할 수 없는 계정에서도 Desktop 개발 플러그인으로 디자인/UX 근거를 수집하고, 대상 서비스의 기존 코드 패턴에 맞춰 구현하도록 돕는 것**이다. 인증, 실행 큐, 저널, 스냅샷은 이 작업을 지원하는 기반이다.

목표 흐름은 `디자인 읽기 → 대상 저장소 분석 → 기존 컴포넌트·토큰·자산 연결 → UX 구현 → 빌드·동작·화면 검증`이다. 설계 시 제공한 Figwright/figma-mcp-rust/figmosha2의 코드와 스킬은 참고 자산이다. 이번 작업에서는 Superpowers 스킬이나 하위 에이전트를 실행하지 않았다.

“코드 패턴 학습”은 저장소 분석과 실제 코드 읽기를 통해 이번 구현에 규칙을 적용하는 것이다. 현재 서비스에 모델 재훈련 엔진이나 임의 서비스의 완전한 자동 코드 생성기가 구현되어 있다는 뜻은 아니다. 디자인으로 관측할 수 없는 비즈니스 규칙, API 동작, 접근성 의미는 별도 근거가 필요하다.

Figma 파일 접근 권한과 플러그인 실행 권한은 필요하다. 일반 개발 플러그인의 `fileKey` 제공을 전제로 해서는 안 된다. Figma는 이 속성의 접근 범위를 제한한다. [Figma Plugin API](https://developers.figma.com/docs/plugins/api/figma/)

**마지막 테스트 클라이언트 수정 후 `verify` 전체를 다시 실행하지는 않았다.** 합산 결과를 한 번의 전체 실행 성공으로 표현하지 않는다. 마지막 전체 실행 시간은 약 598초였다.

Windows에서 무제한 CPU 수 기반 병렬 실행은 ACL/lease PowerShell helper의 실행 지연을 유발했다. worker 4개로 재실행한 단위 테스트에서는 이 실패가 재현되지 않았다. 실제 Desktop·무료 계정·사용자 서비스의 시각적/동작 E2E는 실행하지 않았다. 소스/가짜 플러그인 테스트 통과는 그 검증을 대체하지 않는다.

MCP wire 테스트의 Windows 예산은 인증 상태 준비·페어링·실제 요청·정리의 누적 시간을 포함하도록 60초로 조정했다. 서비스의 전송/실행 timeout은 늘리지 않았다. 테스트 클라이언트는 서비스 기본 도구 예산 30초보다 짧은 15초로 기다리던 오류를 수정하여 `getFollowerBudget`을 사용한다. 실사용 최초 연결 시간과 느린 Windows 환경의 성능 측정은 후속 검증 항목이다.

전체 병렬 실행에서 남았던 구버전 연결 테스트 2개는 단독 실행 시 각각 약 26초에 통과했다. Windows에서는 7개 E2E 파일을 `mcp-e2e` 후속 그룹으로 옮기고 순차 실행한다. 수집한 전체 파일 282개가 고유 경로 282개인 것을 확인하여 테스트 누락/중복이 없음을 점검했다. 빌드된 `dist/code.js`도 Web Crypto/AbortController가 없는 VM에서 초기화와 문서 읽기에 성공했다.

코드는 staging 상태로 정리했으며 커밋·병합·배포는 수행하지 않았다. `review-2026-09-05`는 이번 수정의 범위와 출처를 기록하며 Task 9A/9B/9C/10 전체 완료를 의미하지 않는다.
