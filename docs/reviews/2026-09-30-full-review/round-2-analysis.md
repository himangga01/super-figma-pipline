## Production reachability and counterevidence

**R2-A01 — F04 is avoidable review friction.** A variable initialized by `new Map()` or `new Set()` enters receiver discovery because it accepts call/new initializers, fails network-factory inference, and becomes an unknown receiver. Ordinary `get`/`delete` calls then generate unresolved-client evidence. This matters in C2/C3: production coordinator planning invokes `analyzeServiceGraph` at `coordinator.ts:624-639`; core preparation independently refreshes the graph and invokes selection at `recipes/core-source.ts:254-266`.

However, `service-selection.ts:118-125` accepts an exact owner review bound to the source, callsite index, path, hash, offset and diagnostic code. The round-one “High” assessment therefore overstates the supported planning consequence. Record **High → Medium**, preserving historical evidence rather than silently editing the round-one report. M08 correctly calls this review friction. Classify supported non-network receivers using binding evidence; a shadowed or mutated `Map` name must not acquire a blanket exemption. Keep real imported HTTP clients and unknown factories reviewable.

Meaningful acceptance: a real selected C2/C3 source containing known collection methods produces neither HTTP rows nor spurious review requirements; shadowed constructors, imported HTTP methods and unknown factories still retain the appropriate evidence. Exercise exact owner review separately rather than asserting that every unknown is an unconditional block.

**R2-A02 — F05 retains a false-complete omission.** Direct identifier `fetch` has a lexical-declaration check at `service-connections.ts:664-670`. For a member call such as ordinary `globalThis.fetch('/api/items')`, the receiver has no discovered binding; the supported-member branches at `:696-720` do not recognize it and silently continue. Thus a source can have no client row and no unresolved diagnostic for that call. A complete graph can omit relevant HTTP usage; this is not evidence that its server endpoint is absent, nor a separately proved operational authorization bypass.

M08 must recognize the qualified intrinsic only with lexical/global binding and mutation evidence. A local parameter or declaration called `globalThis`, an aliased object, or overwritten `fetch` is counterevidence to intrinsic recognition. Preserve the existing bare-fetch shadowing protection. Acceptance must assert client rows, unresolved evidence, graph completeness and selected planning behavior independently for direct/qualified calls, shadowed globals, aliases and supported imported clients.

**R2-A03 — F06 survives the T26 consumer challenge.** The source callback in `coordinator.ts:801-818` reads bytes and validates their original checksum, then uses the default UTF-8 decoder. A leading BOM is removed from the returned text. `workflow-requirements.ts:324-334` hashes that text and compares it with the original graph hash; the mismatch discards otherwise verified capability-source evidence. The defect belongs to the handoff between verified bytes and decoded workflow input, not to graph ingestion.

Existing T26 tests in `test/portal/service-connections.test.ts:428-451` distinguish one leading BOM from unrelated/double-BOM text. `service-graph.test.ts:336-364` covers a real BOM-prefixed source with original-byte hash and complete graph evidence. These are substantive repairs and counterevidence to the old accusation that the graph simply cannot ingest BOM sources. They do not exercise the coordinator-to-workflow consumer.

M07 should carry a verified raw-byte digest alongside decoded text through an explicit internal contract. Arbitrary BOM-tolerant hash matching or reconstruction from normalized text would weaken source authority. Acceptance should use the production graph → source callback → workflow requirement path for BOM/non-BOM capability sources, then mutate the original bytes and prove stale identity is rejected.

**R2-A04 — F14 concerns required committed inputs.** Script/SFC module collection skips CSS, and the excluded-input diagnostic relies on collected module references. A supported local stylesheet `@import` can consequently require a committed `build/` or `dist/` token file that the inventory excludes. Exclusion identity binds path/kind/reason rather than those bytes. The CSS token reader's explicit entry-only early return when local custom properties exist does not close imported token coverage. Such a required dependency can be omitted, and changing it need not change the inventory digest.

T26's `service-graph.test.ts:366-399` names required **script** imports into excluded outputs. `source-inventory.test.ts:275-334` deliberately avoids reading 6,000 unrelated generated files and preserves stable hashes for those unreferenced outputs. Both are sound boundaries; neither proves stylesheet dependency closure. M07 must discover supported local CSS dependencies, bind their original bytes when required, and expose unsupported required syntax as incomplete. Reviewed regenerated-output receipts remain separate authority.

Acceptance: a committed local entry imports build/dist tokens, including an entry that already defines its own token. The required imported values and hashes participate; mutation changes source identity; missing/unsupported required imports block clearly. Unreferenced large output trees remain excluded and unread.

**R2-A05 — F15 needs loader proof, not suffix stripping.** The profile recommends component SVG imports with framework-specific queries, while the module resolver looks up the entire queried string against ordinary inventoried paths. A configured loader's valid `icon.svg?react` or `?component` import therefore fails despite an inventoried raw SVG. Reachability is the supported project using that loader configuration, not every project with a similarly named dependency. The profile itself notes that configuration must be confirmed.

M07's current repair boundary is correct: retain the raw asset digest, query semantics and explicit configured-loader evidence. Unknown or incompatible queries remain unsupported rather than silently becoming bare assets. Acceptance needs valid React/Vue loader configurations, the wrong loader, unknown queries, missing raw SVGs and byte changes. Do not equate dependency presence with runtime transform support.

**R2-A08 — M12 remains narrow.** Canonical text capture already requests segments for every text node with the API and preserves leading/tracking and bindings.
