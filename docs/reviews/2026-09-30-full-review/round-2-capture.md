### R2-CAP01: paragraph semantics disappear from canonical capture

**Trigger and exact evidence.** Capture plain locally styled text with numbered/bulleted list options, nested indentation, or local node/run wrapping. The canonical node field list at `shared/src/figma-capture-read.ts:162-177` includes paragraph spacing/indent but omits node `textWrapStyle`. Its segment request at `:264-280` includes font, fills, leading, tracking, decoration, links, style IDs and bindings, but omits `listOptions`, `indentation` and `textWrapStyle`. Chrome's compiled reader (`cli/src/read-program.ts:1-7`) and pinned Desktop's canonical handler (`plugin/src/handlers/portal-capture-read.ts:13-19`) share that function.

The generic serializer knows those segment fields (`plugin/src/serializer.ts:335-353,377-383`) and uniform wrap (`:670-671`), but its list probe at `:684-690` requires a newline. Its own comment admits that one-item single-line lists are missed. `plugin/test/serializer.test.ts:1052-1071` codifies the omission: the fixture's list getter returns UNORDERED, yet the test requires it not to be called. A single paragraph can carry list options; the writer exposes range list, indentation and wrapping writes without a newline requirement (`plugin/src/handlers/set-text-range.ts:113-120`).

**Consequence and root cause.** Semantic capture cannot reconstruct these local paragraph choices. Normalization retains captured tree properties (`mcp/src/portal/design-normalization.ts:290-319`) and hashes the retained tree/catalogs (`:600-608`); it cannot recover absent fields. A change confined to an omitted paragraph field can therefore leave semantic identity unchanged when retained geometry/styles also remain unchanged. The cause is an incomplete canonical field request plus an invalid generic performance shortcut.

**Counterevidence and boundaries.** The canonical reader always requests leading and tracking; F34 remains a generic-only omission. Text-style catalogs preserve some wrap data (`figma-capture-read.ts:450-461,508-520`), which helps style-linked text but cannot recover independent local overrides or missing list runs. Existing capture/reobservation tests protect identity for fields they actually collect. Visual image evidence can still show a rendered difference; this is not proof that every visual acceptance gate is blind.

**Old relation and bounded fix.** This is a new omission adjacent to F34, not a retraction of canonical leading/tracking counterevidence. Add node wrap and run list/indentation/wrap to the shared bounded reader. Preserve them through normalization, schemas and identity. Failed required API reads must remain explicit incomplete evidence. Probe nonempty single-line text for list semantics instead of assuming newline absence proves NONE. M12 now incorporates F41 and this paragraph matrix.

**Meaningful acceptance.** Exercise the actual compiled Chrome program and pinned Desktop handler using plain locally styled numbered, bulleted and nested paragraphs, including one-item single-line lists and independent run wrap. Reobserve the same node ID after changing only a paragraph field and verify the semantic identity changes. Check style-linked and locally overridden text separately, API failure/incompleteness and existing capture bounds. Generic tests must replace the false single-line assumption. Live Figma acceptance remains necessary beyond the host mocks.

### R2-CAP02: batch rollback overwrites a concurrent manual edit

**Trigger and exact evidence.** A batch first renames a node from A to Automated; a later child awaits a host lookup/font operation. The user renames the first node to Manual during that wait; the later child then fails. `batch.ts:372` registers rename with `nodeProps`. That inverse resolves the node again and unconditionally assigns captured values (`:59-64`), overwriting Manual with A. Multi-node restoration (`:88-93`) and typography restoration after awaited font loading (`:190-195`) have the same ownership gap. The batch captures all preimages before application (`:467-469`), awaits children in order (`:474-478`) and undoes them after failure (`:485-493`), providing an actual asynchronous interleaving boundary.

**Consequence and root cause.** The source document loses an unrelated user edit. Unless an inverse throws, `:499-508` calls this `BATCH_ROLLED_BACK`. The mutation wrapper's before/after comparison (`mutation.ts:437-444`) cannot detect the intermediate manual value once rollback has already erased it. The inverse equates successful assignment with authority to restore, without recording and comparing the property's owned post-write value.

**Counterevidence and boundaries.** Annotation rollback already compares current state against the observed before/after states and rejects a conflict (`handlers/set-annotations.ts:37-71`). Preserve that protection. Existing batch tests prove scalar fill restoration (`test/handlers/batch.test.ts:221-238`), real throwing-undo reporting (`:240-270`) and per-corner recovery (`:272` onward); they do not schedule an unrelated edit across an awaited later child. Dispatcher mutation settlement can label a remaining change partial (`dispatcher.ts:89-103`), but it cannot recover an edit erased before settlement. This is a supported asynchronous failure scenario, not a claim that all synchronous host writes are preemptible.

**Old relation and bounded fix.** F30 concerns incomplete mixed typography inverses. This is separate user-edit loss even for ordinary scalar properties. Record owned writes for each affected property/range, including partial writes. Immediately before inverse application, compare the current value with the owned post-write value. Preserve conflicting edits and report an honest partial/conflict result. Preserve ordered ownership when multiple batch children touch the same field. If ownership or exact restoration cannot be proved, reject that operation during read-only preflight or report uncertainty; broad document snapshots or global undo would expand the unsafe overwrite boundary. M12 now incorporates F42.

**Meaningful acceptance.** Delay a later child after the first rename/property write, make a manual edit to the first target, then trigger failure and cancellation through the real batch/mutation path. The manual value must survive; the failure must identify partial/conflicting restoration. Cover typography and multi-node properties, repeated writes to one property, conflicts during inverse lookup/font waits, clean rollback with no edit, partial setters and the existing conflict-aware annotation path. Validate the asynchronous scenario in live Figma as well as deterministic deferred host mocks.
