# 재리뷰 후 구현 및 검증

기준: [2026-09-05 재리뷰](2026-09-05-rereview-ko.md). 사용자 요청에 따라 Superpowers 없이 수정했으며 기존 Chrome에만 연결하는 원칙을 유지했습니다. 원본 오픈소스 디렉터리는 변경하지 않았습니다.

## 핵심 컨셉

Dev Mode와 Figma 자체 MCP가 없어도 개발 플러그인 또는 기존 Chrome의 Playwright/Scripter를 통해 디자인 값을 읽습니다. 대상 저장소의 실제 파일·AST·토큰·컴포넌트·아이콘과 관례를 분석하고, 연결된 코딩 에이전트가 그 근거로 UI를 구현하는 로컬 서비스입니다. 독자적인 모델 훈련이나 미관측 비즈니스 로직 복원을 의미하지 않습니다.

## 추가한 기능

- 공통 `inspection.json`: 원본 관측·시각 근거·코드 분석·자산 목록의 파일 크기와 SHA-256을 연결합니다.
- Chrome 자산: 원본 이미지, SVG, 최상위 프레임 PNG. 수집 한도와 미수집 항목은 목록으로 남깁니다.
- 코드 관례: routing/state/API/import/theme/accessibility/testing 신호를 실제 파일·행·해시와 함께 제공합니다.
- Desktop 연결: 기본 세션 한정 URL 확인, 선택적인 영구 문서 UUID 생성·승인·Undo·재인증.
- 승인 UI: 요청·승인·거절·만료·재연결·취소와 동일 작업의 실행 기록을 연결합니다.
- `snapshot.capture`/`grounding.refresh`: 동일 execution/approval/journal/egress/evidence 경로에서 스냅샷과 그래프를 저장하고 코드 변경을 확인합니다.
- `export_tokens`, `export_frames_to_pdf`, `doctor`, `import_library_variable`. 현재 116 tools, 106 plugin handlers, 10 server-only, 직접 실행 99개와 server adapter 17개입니다.
- 관리 CLI, 빌드 식별 검사, 전경 daemon, 독립 설치 가능한 MCP·CLI·플러그인 패키지, notices·SBOM·checksum·CI 구성.
- `verify:source`: 전체 검증 및 독립 실행이 성공하고 검사 전후 소스 해시가 같을 때만 로컬 검증 보고서를 생성합니다. 실제 Figma/대상 서비스/원격 CI 검증과 구분합니다.

## 검증

첫 전체 실행은 297개 파일, 3,335개 테스트 중 3,308개 통과·10개 실패·17개 건너뜀입니다. 실패는 신규 승인·파일 연결 상태를 제공하지 않던 기존 UI 테스트 대역 2개 파일에 모였습니다. 수정 후 해당 화면 테스트 29개는 통과했습니다. 원본 결과는 [첫 verify 기록](2026-09-06-first-verify.txt)에 보존했습니다.

추가로 CLI 명령 분기 4개, 공통 inspection 변조 거부, 자산 읽기 프로그램, 상세 reaction, 도구 계약, 스냅샷 저장·refresh를 검증했습니다. 전체 재검증에서는 299개 파일·3,323개 통과·17개 건너뜀을 확인했습니다([메모리 최종 수정 전 전체 기록](2026-09-06-pre-memory-full-verify.txt)).

1만 노드·2만 edge 검증에서는 최초 약 142MB를 확인했습니다. 해시를 스트리밍으로 바꾼 뒤 약 100MB로 줄었지만 후속 검사에서 약 145MB가 관측되어 저장 바이트 직렬화도 수정했습니다. 최종 방식은 일반 실행과 pnpm 환경에서 각각 독립 프로세스 3개로 약 70MB를 기록했고, 결과 크기는 동일한 15.63MB입니다. Unicode·청크 경계·SHA-256·정규 JSON 바이트 동등성 테스트를 추가했습니다. 측정은 그래프 생성·스키마 검증·저장 바이트 직렬화 단계의 힙 증가량이며 전체 Figma 호스트의 메모리를 측정한 값은 아닙니다.

패키지 3개의 포함 파일·해시·체크섬과 저장소 밖의 신규 설치가 통과했습니다. 실제 MCP stdio 초기화/도구 조회에서 116개를 확인했고, daemon이 stdin EOF 뒤에도 유지되고 소유한 프로세스만 종료되는 것을 확인했습니다.

최종 `verify:source`는 모든 단계가 통과했습니다. 전체 300개 테스트 파일에서 **3,325개 통과·17개 건너뜀·실패 0개**입니다. 17개는 Windows에서 제외하는 POSIX 검사와 파일 symlink 권한 조건 등을 포함하며 통과로 계산하지 않았습니다. 메모리 3회 측정의 최대 힙 증가량은 **70,995,688 bytes**, 직렬화 결과는 **15,629,525 bytes**입니다. 별도 artifact 테스트 1개도 통과했습니다.

패키지를 같은 빌드에서 다시 생성한 후 3개 아카이브와 manifest의 체크섬이 동일한 것도 확인했습니다. 소스 검증 전후 해시가 동일한 상태에서 생성한 [최종 검증 정보](2026-09-06-validation.json)와 [전체 실행 기록](2026-09-06-final-verify.txt)을 보존했습니다.

최신 daemon을 실행했습니다: PID 57020, loopback 3055, build ID `1788642911203`. 인증된 상태 조회의 build identity는 빌드 파일과 일치했습니다. 연결된 플러그인은 0개입니다. 전환 과정에서는 제가 앞서 시작한 이전 세션만 종료했으며, Figma 앱이나 Chrome을 종료·재실행하지 않았습니다.

최신 Desktop 번들은 `%LOCALAPPDATA%/SuperFigmaPipeline/desktop-plugin/manifest.json`에 준비했습니다. 최초 등록 후 해당 파일에서 플러그인을 실행해야 합니다. 페어링 코드가 만료되었으면 `connect`를 다시 실행하여 같은 번들을 갱신합니다. 공유용 로그 사본은 줄끝과 행끝 공백만 정규화했고, 해시로 묶인 검증 로그 원본은 `service/artifacts/source-checks/`에 유지합니다.

## 외부 상태 때문에 남아 있는 검증

1. Figma Desktop의 실제 계정 연결: 해당 파일이 열려 있으나 네이티브 제어 파이프가 연결되지 않아 최초 플러그인 등록/실행을 조작하지 못했습니다.
2. 최신 Chrome 실파일·자산 캡처: 마지막 확인 시 Chrome 프로세스가 없습니다. 기존 세션이 열리고 원격 디버깅 연결이 가능해야 합니다.
3. 실제 대상 서비스 구현·반응형·상호작용·화면 비교: 구현할 저장소 경로가 아직 제공되지 않았습니다.
4. 원격 CI: workflow를 구성했으며 원격 실행 결과를 주장하지 않습니다.

이전 11개 최상위 항목/3,198개 노드 캡처는 과거 검증입니다. 이번 변경의 실파일 검증이나 실제 서비스 구현 완료로 대체하지 않았습니다.
