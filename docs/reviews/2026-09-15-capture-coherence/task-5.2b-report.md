## Coherence, checkpoints and bounds

Each attempt performs a complete bounded read, exports assets, then performs another complete bounded read. Each read itself retains the reviewed ordered query reobservation. Both normalized semantic content and the reader's supported content identity must match. Same-ID tree/style/variable/reaction changes discard the affected whole attempt. At most two attempts execute under one 300-second deadline. Changes detected inside the reader also invalidate/retry an attempt within this bound.

No checkpoint asset is reused across attempts, including immutable originals. Every new attempt uses a fresh folder and exports PNG/SVG observations again. Immutable original image hashes are deduplicated only within that attempt. Existing capture-progress is updated only after a matched completed observation, including an explicitly incomplete observation. The immutable designs record is never changed by this capture port. A failed retry preserves the earlier coherent progress record.

Signed capture-attempts records preserve the source/raw snapshot, folder, known asset manifest and started/assets-exported/changed/observed boundary. A failure before a manifest returns retains the start record and its attempt folder rather than claiming a complete manifest. They are inspection evidence, never resumable execution authority.

The fallback remains atomic: false. It cannot detect transient ABA changes, unsupported property surfaces or changes after an earlier query's final reread. No supported durable document epoch was available in this collector, and none was invented.

Bounds are two attempts, 512 batches per attempt, 100,000 asset records per attempt and 536,870,912 logical asset bytes across both attempts of one capture call. New export bytes remain bounded by 64,000,000 per batch and individual original reads by 16 MiB. Prior in-attempt assets are all byte/hash/size verified and reserved before any new asset allocation. Repeated owner-history captures and their diagnostic records are not globally quota-managed by this change; 512 MiB is not a claim about all retained owner history. Existing visual verification's 128 MiB oracle subset reader and artifact paging limits are unchanged and must remain explicit in later acceptance integration.
